01产品定位与核心使用场景

一句话：把「同一个选题写三遍」的重复劳动，变成「一次事实梳理 + 三次有依据的重组」。

定位

单人使用、本地优先的内容生产工作台，只服务 AKA张猩猩 一个账号，覆盖抖音、小红书、公众号三个平台。它不替代你的判断，只负责三件事：把资料沉淀成可复用的底座、把平台差异固化成可执行的规范、把质检结论落到具体段落。

这不是发布工具，也不是热点雷达。所有产出终点是「可复制的文本 + 可归档的 Markdown」，发布始终由你或剪辑方手动完成。

与旧工作流的关系

你原有的「抖音视频账号分析」库是三账号、纯抖音的流程。本应用是重构版：只做 AKA张猩猩，扩到三平台。旧库中的口播听觉规则、低 AI 味风格手册、CTA 模板、违禁词库可作为参考与规则来源，但不在本应用中整套继承，也不写回旧库目录。

核心场景

A · 开工
新选题进池，写清来源、目标平台、优先级。资料没就绪就不进创作。
B · 备料
链接、文件、原话堆进资料区，逐条标为事实 / 观点 / 推断 / 待核实，形成事实底座。
C · 出稿
同一底座，三平台各自按结构要求出稿；抖音先出大纲给你确认方向，再出分镜脚本。
D · 复查归档
四道闸质检给出可定位的问题，改完留版本；定稿写进 Obsidian，排期上标出发布日期。

明确不承担的事

  • 不声称任何选题「当前很热」——除非有明确数据来源并标注检索时间。
  • 不自动发布到任何平台——没有账号授权就不存在这条链路。
  • 不承诺内容合规——只按你确认的词表与规则做提示，不替代平台审核。
  • 不编造真实使用体验、截图、翻车细节和数据。

02产品模型：对象与状态

全文档的公共语言。字段、状态、规则都以这里为唯一口径。

对象关键字段说明
选题 Topic名称、来源、立意、内容类型、目标平台、优先级、状态、排期日、标签、账号账号固定为 AKA张猩猩，字段保留以便将来扩展。目标平台可只选其中一两个。内容类型是选题属性，不是平台属性。
资料条目 Material类型、原始内容、来源、分类、核实状态、备注选题私有。四类：事实 / 观点 / 推断 / 待核实。
素材片段 Snippet文本、分类、来源、标签跨选题复用，多对多；引用时快照进选题，避免后续改动影响已定稿内容。
大纲 Outline钩子、核心论点、结构、待验证假设、发布文案、封面文案抖音专属前置产物；需你确认方向后才允许生成分镜脚本。
稿件 Draft选题、平台、来源、状态、当前版本、时长、投流标记、商单标记一题一平台一份稿件，多份历史版本。平台只决定形态（分镜脚本 / 图文笔记 / 长文），内容类型继承自选题，不单独设置。投流与商单标记默认收起，勾选后才展开对应 CTA 判定。
版本 Revision版本号、正文、来源、Prompt 快照、时间、质检摘要每次保存新增一条，只增不改。
质检报告 QCReport所属版本、闸门结果、命中项、采纳状态、AI 参考记录绑定具体版本；改稿需重跑。
排期项 Schedule选题、平台、计划发布日、状态一题多平台可多条。
规则 RuleID、平台、检查项、阈值、严重级别、启用状态内置默认值，可逐条改阈值与开关，改动留记录。
Prompt 模板平台、正文、变量说明、版本可编辑、可回滚；生成记录保存当时快照。
候选选题 Candidate标题、来源、来源链接、检索日期、推荐理由、状态来自选题雷达或定期补充，采纳后转为正式选题。

内容类型（选题级）

内容类型挂在选题上，一个选题一个类型，三个平台共用。同一选题在抖音、小红书、公众号各出一份内容时，三份的类型完全相同——平台只改形态与结构要求，类型决定内容要求。

类型一句话特征主要约束（第 07 节 T 系列）
教程把一件事拆成别人能照做的步骤；复盘是它的过去时形态步骤可执行、前置条件、坑位与代价、结果可验证
测评在同一组维度上比较两个以上对象维度一致、参数与价格溯源、结论取舍
观点提出一个主论点并回应反方；行业观察是它的外部视角单一主论点、论点支撑、预设反驳、来源与时间、事实与推测分离、预测边界

只有三类。复盘不单列——它是教程的过去时，按教程建选题，规则额外要求过程与结果可核对；行业观察也不单列——它是观点的外部视角，按观点建选题，规则额外要求来源与时间、推测标注。一个选题确实跨两类时，只选主类型，另一类作为正文里的章节存在，不新增第二个类型字段。

选题状态机

状态进入条件可去往
待整理仅录入名称与来源资料就绪、已搁置
资料就绪至少 1 条资料，且无未分类条目创作中、待整理、已搁置
创作中任一目标平台稿件存在待质检、已搁置
待质检至少一份稿件标记「已完成，待检查」创作中、已归档
已归档所有目标平台稿件为「可归档」或「已放弃」，且已写入 Obsidian创作中（回炉）
已搁置手动待整理、资料就绪、创作中

状态由系统按条件推导，不允许手动跳级；「已搁置」是唯一可手动回退的例外。

稿件状态机（按平台独立）

状态进入条件说明
未开始选题已建，未出稿显示「生成」入口
待大纲抖音：仅有资料，未出大纲抖音专属前置状态
待确认方向大纲已生成，等你确认未确认不允许出分镜
草稿生成结果落库或人工回填来源标「生成 / 人工回填」
待修改质检存在阻断级问题可继续编辑
可归档无阻断问题且无未采纳建议，或已全部忽略允许写入 Obsidian
已归档写入成功再编辑回「草稿」并要求重跑质检
已放弃手动保留记录，不计入完成度

断点与恢复路径

断点系统行为你的恢复动作
链接抓取失败保留 URL，标记失败原因（超时 / 非 2xx / 正文为空 / 需登录），不写入任何正文手动粘贴，或改为「仅记录链接」
文件解析失败保留文件名与原因，提示扫描件需先转文本转存 TXT/MD 后重新导入
大纲方向被否保留原大纲为 v1，记录否决原因改角度重出大纲，或直接手写
回填内容结构不符列出缺失场次/章节，允许存草稿，不允许进质检补齐结构或重新生成
质检阻断定位到段落或场次，给建议逐条修改，或标记忽略（需填理由）
Obsidian 写入失败保留归档任务，显示具体原因修正路径后重试，或导出到本地
目标文件被外部改动写入前比对指纹，不一致则中止并展示差异覆盖 / 另存新版本 / 放弃

04功能模块与页面结构

七个页面，每页只承担一类工作。

页面核心问题关键区域
今日工作台今天该干什么？本周排期、卡在质检的稿件、待确认的大纲、资料未就绪的选题、素材缺口
选题池有哪些题，到哪一步了？正式选题 + 候选选题两个视图；状态/平台/优先级筛选与搜索
选题详情这个题的资料和稿子在哪？状态条、资料区、三平台稿件卡、质检入口、素材缺口
创作台怎么出这一份稿？左资料速览、中 Prompt 组装与回填、右结构校验与真实性标注
质检台具体哪里有问题？四闸结果、问题定位、改前改后、采纳与忽略
排期看板哪天发什么？周视图按平台分色；拖拽只改日期
规范与模板规则和 Prompt 怎么改？规则开关与阈值、Prompt 版本、词表、参考资产同步

全局状态条

左侧固定导航，顶部常驻状态条显示四项：数据目录、Obsidian 归档目录是否可写、违禁词库词数与更新时间、今日待办数。异常直接标红并可点开，不藏在设置里。

设计约束

所有列表页一屏可见「状态 + 平台 + 最近更新」；所有操作必须有反馈，成功给撤销入口，失败给具体原因与下一步；不做无数据支撑的图表。

05功能需求

按「目的 / 输入 / 处理 / 输出 / 异常」描述，作为开发与验收的共同依据。

FR-01

选题管理

选题池是唯一入口，避免选题散落在聊天记录与备忘录里。

输入
名称（必填，≤60 字）、来源（自由文本）、立意（≤120 字）、目标平台（可多选，默认全选）、优先级、计划发布日（可选）、标签。
处理
创建后为「待整理」；目标平台决定详情页稿件卡数量；排序规则为「有排期日按日期 → 无日期按优先级 → 同优先级按创建时间」。
输出
卡片列表、自动状态推导、按名称/标签/来源筛选搜索。
异常
同名选题允许存在但创建时提示；删除需二次确认，已归档选题删除只移除索引，Obsidian 文件保留。
关于热度

系统不做热度打分、不给「推荐选题」。候选选题必须带来源链接与检索日期，无来源的不入库。

FR-02

资料整理

把「我查到的」和「我以为的」分开存放，这是三平台内容不出错的唯一保障。

输入
粘贴文本；链接登记（URL + 标题 + 摘要）；自动抓取链接正文；导入本地文件（TXT / MD / PDF / DOCX）；图片只登记不解析。
处理
每条资料必须落入四类之一：事实（可引用、有出处）/ 观点（他人或自己的看法）/ 推断（基于资料的推理）/ 待核实（有疑点）。抓取与解析结果先预览再落库。未分类条目视为资料未完成。
输出
按分类分组的资料列表、完整度提示（如「3 条事实 / 1 条待核实」）、可复制的资料摘要块。
异常
抓取失败区分四类原因并保留 URL；文件 >20MB 或 >100 页提示分段导入；扫描件提示需 OCR。
FR-03

跨选题素材复用

一个数据、一个案例往往服务多个选题。

输入
资料条目「存入素材库」，或直接新建片段（文本 + 分类 + 来源 + 标签）。
处理
引用时复制快照进选题资料区并保留来源链接；修改源素材不影响已引用内容，只提示「已更新，是否同步」。
输出
素材库列表（标签筛选、引用次数）、引用关系可追溯。
异常
仍被引用的素材删除时只标记「已停用」。
FR-04

两段式创作：大纲 → 确认 → 成稿

抖音必须先把方向定下来再写长稿；小红书与公众号可直接成稿，也可选用大纲。

输入
选题信息、已分类资料、目标受众、内容类型（选题级，三平台共用：教程 / 测评 / 观点）、时长（抖音固定 3–5 分钟）、平台规范、Prompt 模板、投流标记、商单标记。
处理
抖音：先生成大纲（钩子 / 核心论点 / 结构 / 待验证假设 / 发布文案 / 封面文案），状态转「待确认方向」；你确认或改写后才允许生成分镜脚本。三平台都执行结构校验；校验不通过可存草稿、不可归档。
输出
结构化正文、该次 Prompt 快照、来源标记（生成 / 人工回填）、结构校验结果。
异常
资料为空禁止生成；模板变量缺失时高亮；生成中断保留输入不丢草稿；大纲被否时保留为 v1 并记原因。

成稿结构约定（结构校验的依据）

  • 抖音 · 分镜脚本：头部元数据（账号 / 时长 / 产品 / 封面文案 / 发布文案 / 投流 / 商单）+ 场次表（场次、景别、时长、画面描述、字幕or配音、花字、素材来源/状态、反馈）+ 纯口播稿（只留文字，段间空行，不含镜头号与时间戳）。
  • 小红书：标题 / 正文 / 配图建议（编号，每张一句）/ 话题标签。
  • 公众号：标题 / 开篇 / 章节小标题（可多个）/ 结尾。

解析失败时明确显示「未识别到 XX 结构」，并标出已识别部分，便于手工补齐；不做「大概齐」的猜测。

真实性标注（硬规则）

稿件中凡出现「真实体验 / 截图 / 翻车 / 具体数据」，必须能追溯到资料区里的对应条目。不能追溯时，在对应句子后插入标记 ⚠️ 真实性待补，并在质检中以阻断级报告。国外 AI 工具默认使用代称（某海外 AI 工具），除非你确认已取得推广授权。

FR-05

三平台差异化组织

三份稿子共享同一事实底座，但各自重组，不做互转。

平台必须重组的地方禁止
抖音前 3 秒钩子；按 7 字/秒折算字数；单句 ≤40 字；每段对应镜头；结尾复述核心信息把公众号段落直接朗读化；书面连接词堆叠；一次成功无波折
小红书标题给利益点；前三行给结论；正文分 3–5 点；配图逐张说明长段落；无分点整块论述；外链导流
公众号开篇 200 字内建立问题；每章小标题；章节间承接；结尾收束只做要点罗列；章节无递进
FR-06

质检

把「感觉不太行」变成「第 3 场第 2 句是书面语，建议改成……」。

输入
某一版正文 + 平台 + 投流/商单标记 + 词表 + 资料分类结果。
处理
按四道闸顺序执行（详见第 07 节），结构先行，避免先改文字再返工。每条命中产出规则 ID、级别、定位（场次/章节 + 段落 + 原句）、依据、建议。可逐条采纳或忽略（忽略需理由）。
输出
绑定版本的报告、按级别统计、改前改后对比、可复制的问题清单。
异常
正文为空或结构未通过时不执行后三闸；阈值改动后旧报告标「规则已变更」。
边界声明

质检只能发现本方案列出的可判定问题。不能识别所有违规内容，不能保证平台审核通过，也不做法律判断。违禁词命中只代表「必审」，不等于「违规」。

FR-07

版本与对比

改稿是常态，必须能回到任意一版并看清改了什么。

处理
每次保存 / 生成 / 回滚都新增版本，记录来源、时间、Prompt 快照、质检摘要。对比用段落级 + 句级差异。
输出
版本列表、两版并排对比、回滚（回滚本身也产生新版本）。
异常
内容无变化时不产生空版本。
FR-08

排期看板

知道哪天要发什么，而不是临到头才想起来。

处理
按周展示，一题多平台各占一条；颜色区分平台，角标显示稿件状态；拖拽只改日期不改状态；未定日期进「待排期」区。
输出
周视图、待排期清单、临期提醒（计划日已过且未归档标红）。
异常
同平台同日 >2 条时提示冲突但不阻止。
FR-09

归档与 Obsidian 写入

定稿即入库，不需要二次搬运。

输入
可归档的版本、选题信息、质检结论。
处理
应用为唯一真相源。写入 Obsidian 主库下 内容工作台/，生成带 frontmatter 的 Markdown（选题 ID、平台、账号、状态、版本、时长、投流、商单、质检结论、更新时间、标签），正文顶部附选题索引链接；同步更新索引文件。
输出
Obsidian 文件 + 归档记录（路径、时间、文件指纹）。
异常

  • 资料四通道录入（粘贴 / 链接登记 / 文件导入 / 抓取）、分类与核实状态。
  • Prompt 组装、大纲与成稿、结果回填、结构解析与校验、三平台独立状态。
  • 四道闸质检（H/S/C/V/X 规则集）、定位到段落与场次、采纳与忽略。
  • 版本记录、差异对比、回滚。
  • 写入 Obsidian、frontmatter、索引维护、冲突检测。
  • 全量导出与滚动备份。

需要前提 有外部条件才成立

  • 链接正文抓取：需网络且站点可访问。登录墙、付费墙、反爬、动态渲染会失败，只报原因不伪造。覆盖率无法承诺。
  • PDF / DOCX 提取：扫描件与图片型 PDF 无法提取文字，需先转文本或 OCR。
  • Obsidian 写入：需 macOS 授权该进程访问「文稿」目录，且库路径存在；首次可能触发系统权限弹窗。
  • 选题雷达导入：依赖 02_内容规划/选题池/ 文件存在且格式稳定；格式变了就导入失败，不猜。
  • 违禁词库：依赖本地词库文件；词库过期只影响覆盖面，不影响其他功能。
  • 一键生成与 AI 审阅：需可用 LLM API Key 与网络（本期不启用，留接口）。

只能人工 本方案不做，也不假装做

  • 热点判定与选题推荐：无平台数据授权，不做热度打分；候选必须带来源与日期。
  • 平台发布：无账号授权，只提供复制与导出。
  • 合规判定：不做法律判断，不保证审核通过；词库命中只是「必审」信号。
  • 语义质量与语境豁免：引号内反面示例、版本序数等是否豁免，由你判定。
  • 事实核验：只能提醒「待核实」，不能替你核实。
  • 画面与成片合规：BGM、字体、肖像、logo 水印、画质等归剪辑方，应用不检测视频。
  • 图片内容识别：图片只登记，不解析内容。

风险影响对策
